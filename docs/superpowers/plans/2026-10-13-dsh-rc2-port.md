# DSH Step Risk 0.2.0 Implementation Plan

> Execution: implement in this chat with `dev-tdd` and `dev-verify`; delegate native client and runtime verification as bounded parallel tasks.

**Goal:** Make the current independent per-step failure estimate usable as a DeepSeek Harness V0.2.0-rc.2 plugin in this repository and the installed desktop application.

**Architecture:** Observe real Cordis `session/event` step boundaries and structured tool results. Reuse the Codex `step-failure-chain-v1` rules model, retain the existing attribution fields only for compatibility, persist bounded structured snapshots, and expose a native per-session client panel through a read-only Host route.

**Tech Stack:** ESM JavaScript, Node.js 24.21.0 bundled with DSH, DSH Cordis bundle patch, native client module loader and React supplied by DSH, Node test runner.

## Global constraints

- Exact compatibility target: `0.2.0-rc.2`, official tag `dsh-v0.2.0-rc.2`, commit `639ed015397290b3745d163aafe02ffee4aa3f84`.
- Project: this `dsh-step-risk` checkout.
- Preserve the current Codex checkout and unrelated profile configuration.
- Each DSH step is one model call plus its requested tool executions. Emit one prediction at `step/end`; model-only steps have an unknown outcome.
- Percentages are independent conditional-chain model estimates; no empirical calibration or causal-certainty claim.
- Default persistence contains structured fields only. No prompts, tool arguments, response text, error text, credentials, or external model calls.
- Request-error waterfall must call `next()` exactly once. Observation/persistence/display failures must not interrupt the agent.
- Native client polling must stop when the panel is hidden/disposed.
- Local install is reversible and backed up. No public publishing is requested.
